# 0002 – Pixi für das gesamte Repository

- **Status:** angenommen (2026-10-02), Change `add-slideshow-mvp`
- **Ergänzt:** ADR 0001 (dort waren noch uv und ein Makefile vorgesehen)

## Kontext

Das Repo mischt Python (Backend), TypeScript (Web-App), GLSL (Shader) und
FFmpeg als native Abhängigkeit. Bisher brauchte man dafür uv, Node mit pnpm,
ein lokal installiertes FFmpeg (lokal war es Version 4.3) und ein Makefile.
Der Product Owner wünscht, dass **alles, was über Pixi verwaltet werden kann,
über Pixi verwaltet wird**.

## Entscheidung

- `pixi.toml` + `pixi.lock` im Wurzelverzeichnis, Kanal conda-forge,
  Plattformen linux-64, osx-arm64 und win-64.
- Über Pixi kommen: Python 3.13, Node.js 24, pnpm 10, FFmpeg ≥ 7, Biome,
  glslang, Ruff, Mypy, Pytest, httpx2, jsonschema sowie alle
  Laufzeitabhängigkeiten des Backends. Das Backend ist als editierbares
  PyPI-Paket eingebunden (`mmy-backend`, Build-Backend hatchling).
- **pnpm** verwaltet nur npm-Pakete, die es auf conda-forge nicht gibt
  (React, Vite, TypeScript, dnd-kit …). `packageManager` in `package.json`
  muss zur pnpm-Version aus Pixi passen; das prüft die CI.
- **Pixi-Tasks** sind die einzige Befehlsschnittstelle (`dev`, `check`,
  `test`, `gen-api`, …). Es gibt kein Makefile und kein uv mehr.
- Umgebungen: `default` (mit dev-Werkzeugen) und `prod` (Backend-Image).
- `PYTHONNOUSERSITE=1` in der Aktivierung: Pakete aus `~/.local` dürfen sich
  nicht einmischen. Das ist lokal tatsächlich passiert, ein altes `websockets`
  hat uvicorn abstürzen lassen.
- CI: `prefix-dev/setup-pixi` mit `locked: true`, dann `pixi run check`.

## Konsequenzen

- (+) Ein frischer Rechner braucht nur Pixi. FFmpeg-Version und Toolchain
  sind gelockt und auf allen Rechnern gleich.
- (+) Das Docker-Image baut die gelockte `prod`-Umgebung, ohne zweite
  Quelle für Abhängigkeiten.
- (−) Zwei Lockfiles (`pixi.lock`, `pnpm-lock.yaml`). Das ist unvermeidbar,
  solange npm-Pakete nicht auf conda-forge liegen.
- (−) conda-forge hinkt PyPI und npm gelegentlich hinterher.
- (−) Pixi braucht einen beschreibbaren Cache (`PIXI_CACHE_DIR`, siehe README).
